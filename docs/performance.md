移除未使用的 `nuxt-swiper`、`hls.js`、`remark-toc`。Swiper 的全局样式此前也被内联到页面中；清理后，常规页面的 HTML 减少约 18 KB，全站 CSS 从 158,019 B 降至 140,216 B。新增取消与容错逻辑使全站 JS 输出略增约 4.4 KB（约 0.3%），主要收益是减少重复计算、绘制、无用数据与后台任务。

`pnpm perf:report` 读取 `.output/public`，也可以指定其它产物路径和 JSON 报告路径：

```sh
node tools/performance-report.mjs .output/public report.json
```

`bundles` 是全站输出分块总量，包含懒加载资源；`referencedJs/Css` 是 HTML 直接引用或预加载的文件总量，不是完整依赖闭包。`gzip` 为本地逐文件压缩估算，`flowNodes` 是 SSR 节点元素数。这些指标不是线上传输量、LCP 或真实设备帧率。

## 运行时优化

- 流程图：缓存节点与邻边索引；循环图排序维护活动节点度数，减少反复扫描；减少排序中的临时数组。47 组旧、新布局的完整 JSON 相同，包括坐标、连线、标签、自环、平行边与真实大图。
- 设计画廊：保持 shader 不变，只跳过输入完全相同的重复绘制。固定时间序列的 120 次静态 tick 从 120 次绘制降至 16 次；120 帧连续过渡、拖动和指针变化仍全部绘制。尺寸、DPR、图片变化会强制重绘。
- 转场与噪点：缓存固定粒子参数，复用相同尺寸的画布，空画布不重复清除。100 个转场帧与 1,200 个噪点帧的旧、新绘图输出一致；未降低粒子数、清晰度或修改动画时长。
- 首页 D3 图：稳定连线键，缓存节点与连线 selection，隐藏标签页时停止模拟，离开页面时清理计时器、过渡和监听。
- 图片与文字：复用预加载逻辑，处理缓存命中、失败、空集合与卸载；文字扰动效果最多保留一个待执行计时器，保留逐字及轮播间隔。
- GitHub 卡片：并行加载元数据与列表，共享在途请求和五分钟成功缓存；失败可重试，一个组件取消不会中断其它订阅者。
- 图片预览：取消未完成的图片下载，防止旧复制任务覆盖新状态，清理反馈计时器。浏览器已经接收的系统剪贴板写入无法撤回。
- 本地工具：存储被禁用或 JSON 损坏时仍能使用；渲染函数不再隐式修改产品列表；离开页面时清理文件读取任务。
- About：避免服务端访问 `document`，恢复完整 SSR 内容。字体 TTF 回退路径统一为文件实际大小写。
- Markdown 高亮：服务端在并发高亮前一次载入已配置的语言，消除 Shiki 重载嵌套语言时 `md` 暂时不可用的窗口；保留现有语法、代码示例与调色。直接声明现有 Shiki 1.3.0 构建依赖，语言包不进入客户端分支。

## 验证方式

`pnpm test` 不新增测试框架依赖，包含 47 组流程图、2 项输入校验、5 项图索引/目录/异步复制交互，以及 8 项请求共享、图片加载、本地存储与文字计时器回归。可选提供旧版源码逐项比较布局：

```sh
node tools/check-content-flow.cjs path/to/previous-content-flow.ts
```

高亮回归直接调用项目安装的 MDC/Shiki：15 个真实 Markdown 示例与 23 种语言交错执行 360 次高亮，验证示例文本、初始化后无额外语言重载、客户端不包含语言注册表。

最终 `pnpm test` 通过；`pnpm generate` 成功生成 115 个路由，日志中 HTTP 500 为零。组件示例页在浏览器中正常显示 16 个高亮代码块与 109 个流程图节点。

绘制次数与布局计算时间是受控实验。计时会随机器负载波动，不作为 CI 的速度阈值；验收以结果正确、资源减少和消除重复工作为主。

静态 SSR 对照确认 Book、Security、Design、Plan、Link 的正文、链接、图片属性和完整 DOM 结构一致（忽略生成 hash、脚本、样式标签和注释）。About 的基线 HTML 无正文，新版已正常输出。

浏览器验证覆盖站内导航、书库外观、设计页暂停/作品选择/下一张、真实 106 节点流程图、节点详情、390 px 布局与计算器记录刷新恢复。流程图实测：移入不足三秒时滚动页面，三秒后滚轮操作图，移出恢复页面滚动；门限保持三秒。

CI 使用 Node.js 22 与 pnpm 缓存，并在生成前执行回归测试。

## 长文章刷新与按需初始化

补充检查 `/book/seven-languages-in-seven-weeks-bruce-a-tate`：原页面有 8,166 个正文元素、92 个代码块，刷新时一次性初始化全部 Markdown。列表查询和流程图的优化没有覆盖这个场景。

大型书籍正文现在按完整块分段，标题与其目录标记、第一段正文保持在一起，代码、表格和交互组件内部不拆分。该文章在实际高亮 AST 下分为 42 段。直接访问或刷新时，首段优先初始化，其他段保留服务器生成的 HTML；接近视口 1,200 px 时，每帧最多启动一个排队段。`content-visibility: auto` 同时跳过远处的排版与绘制，打印时恢复完整布局。

这是减少浏览器初始化和排版的工作量，不是减少文章正文传输量；SSR 全文、浏览器查找、目录和锚点仍保留。已激活的段不会在滚出视口后卸载，站内跳转使用正常渲染，短文章不分段。Vue 3.4 的静态 HTML 与活动节点切换有单独回归测试，覆盖全文不丢失、取消、键盘焦点、首次点击和每帧调度。

桌面及 390 px 手机刷新实测：首屏 1 段处于活动状态、41 段保持静态；活动正文元素为 41，完整正文仍为 84,693 字符、92 个代码块、96 项目录。跳到末尾章节后只增加目标附近的段。该数字表示初始化工作量，不表示总 DOM 数减少，也不等同于耗时缩短的百分比。

MathJax 的 `mjx-container` 与 SVG 后代按原生标签渲染，消除将 `g/path/use/text` 误判为 Vue 组件的重复警告；生成的公式 CSS 保留原始文本，修复 SSR 样式字符转义不一致。实际公式的路径、引用、属性及文本均有 SSR 对照测试。移动端视口属性单独同步，避免初次挂载期间重渲染整篇 Markdown；带锚点直接访问/刷新会等待 Logo 解锁与目标段激活后定位并恢复焦点。

Nuxt Content 2.12 的旧解析缓存不包含自定义 transformer 源码。修改 transformer 后，开发服务需要重启并清理 `.nuxt/content-cache`（仅生成缓存）；生产重新生成会重建解析内容。性能报告已加入该长文章与分段计数，避免只以列表页和流程图作为验收样本。

## 其它边界

Three.js 仍为较大的按需分块，未为减小体积删除 WebGL 效果。公共资源运行时解析提示和 Nitro cache-driver 提示仍需单独处理。开发工具的 fs.Stats 弃用调用、Browserslist 数据和依赖预编译警告已在后续[兼容修复](development.md)中处理。

Money 的资金分配公式未改。复审发现原有小额余额（如 84–99 元）的应急金额四舍五入可能超过总余额，需另行修订业务规则并增加金额守恒测试。
